# 기능 명세 (Features)

> Bookmark Alive의 **각 기능이 어떻게 동작하는지** 상세 정의.
> PRD §3의 4단계 프레임(임포트 → 분류 → 위생 → 검색)에 맞춰 구성.

---

## 1. 스마트 임포트 (Import)

### 1.1 브라우저 통합 가져오기
- **지원 브라우저**: Chrome(1순위), Whale(2순위), Safari(3순위)
- **입력 방식**
  - HTML 북마크 파일 업로드 (모든 브라우저 공통 폴백)
  - Chrome Bookmarks API 직접 연동 (크롬 익스텐션 설치 시)
- **처리 동작**
  1. 파일/API로부터 북마크 트리 파싱
  2. 중복 URL은 1차 필터링 (동일 URL은 하나로 병합)
  3. 사용자에게 "총 N개 발견, 예상 소요 시간 M초" 미리보기 제시
  4. 확인 시 일괄 저장 + AI 분류 큐에 투입

### 1.2 폴더 구조 유지
- 기존 폴더 계층(depth 최대 5단계)을 그대로 재현
- 빈 폴더는 옵션으로 스킵 가능
- 임포트 후에도 원본 폴더명 태그로 보존 (예: `#원본폴더_디자인레퍼런스`)

### 1.3 UX 디테일
- **진행률 표시**: 임포트 중 실시간 프로그레스 바
- **중단·재개**: 큰 규모(1000개 이상) 임포트 시 백그라운드 처리 + 중단 시 이어서
- **실패 처리**: 파싱 실패 링크는 별도 리스트로 분리, 수동 확인 가능

## 2. AI 분류·태깅 (Classify)

### 2.1 카테고리 자동 할당
- **기본 카테고리 세트**: 디자인, 마케팅, AI 도구, 개발, 영감, 참고자료, 기타 (7개)
- **커스텀 카테고리**: 사용자가 직접 추가·수정 가능
- **동작**
  1. URL 접근 → 메타데이터(title, description, OG tags) 추출
  2. 본문 일부 스크래핑 (최대 2000자)
  3. LLM으로 카테고리 분류 (confidence score 포함)
  4. confidence < 0.6일 경우 "분류 필요" 상태로 별도 표시

### 2.2 스마트 태그 자동 생성
- 본문 핵심 키워드 3~5개 추출 → 해시태그화
- 형식: `#키워드_상세` (예: `#포토샵_브러시`, `#상세페이지_인스타`)
- 사용자가 태그 수정·삭제 가능
- 자주 쓰는 태그는 상단 고정

### 2.3 3줄 요약
- LLM으로 본문을 3문장 이내 요약
- 카드 뷰에 요약문 표시 → 클릭 전에 내용 파악

### 2.4 UX 디테일
- **분류 미리보기**: 임포트 후 "AI가 이렇게 분류했습니다" 확인 화면
- **벌크 수정**: 잘못 분류된 다수 항목을 한 번에 재지정

## 3. 데이터 위생 (Hygiene)

### 3.1 데드 링크(404) 탐지
- **스캔 주기**: 주 1회 자동 (설정에서 매일/매주/안 함 변경 가능)
- **판정 기준**: HTTP 상태 코드 4xx/5xx 2회 연속 발생
- **처리 옵션**
  - 삭제 권고 (사용자 확인 후 일괄 삭제)
  - 아카이브 모드 (Wayback Machine 링크로 대체)
  - 무시 (태그 `#데드링크`만 부여)

### 3.2 중복 제거
- **판정 기준**: URL 정규화(쿼리 파라미터 제거) 후 완전 일치
- **처리**
  - 동일 URL이 여러 폴더에 있으면 "중복 발견" 알림
  - 사용자가 대표 위치 선택 → 나머지 자동 정리
- **유사 링크**: 도메인·경로가 유사한 경우 "관련 링크일 수 있음" 제안

### 3.3 UX 디테일
- **정리 대시보드**: "정리가 필요한 링크" 섹션에 한데 모아 보여줌
- **일괄 처리**: 체크박스로 여러 개 선택 → 한 번에 삭제/아카이브

## 4. 초고속 검색 (Find)

### 4.1 전체 텍스트 검색
- **검색 범위**: 제목 + URL + 태그 + AI 요약 본문
- **검색 방식**
  - 즉시 검색 (타이핑 시 실시간 결과)
  - 키워드 하이라이트
  - 한글·영문·특수문자 모두 지원
- **고급 필터**
  - 카테고리 / 태그 / 저장일 / 마지막 클릭일 / 폴더

### 4.2 UX 디테일
- **검색 단축키**: `Ctrl+K` / `Cmd+K` 로 어디서든 검색창 호출
- **최근 검색어**: 상위 5개 저장
- **검색 결과 정렬**: 관련도 / 최신순 / 클릭순

## 5. 카드 컴포넌트 명세

카드는 Bookmark Alive의 **핵심 UI 단위**. 두 가지 변형이 있음.

### 5.1 표준 카드 (대시보드 그리드용)

```
┌─────────────────────────────┐
│  [OG 이미지 썸네일]          │  ← 16:9 비율, 없으면 파비콘 + 배경색 폴백
│                             │
├─────────────────────────────┤
│  [카테고리 배지] [추천 레이블] │  ← 예: "디자인" / "📅 작년 4월 저장"
│  링크 제목 (최대 2줄 표시)   │
│  AI 요약 (1~2줄 미리보기)   │
│  저장일 · 도메인명           │
└─────────────────────────────┘
```

| 요소 | 표시 기준 | 없을 때 |
|------|---------|--------|
| OG 이미지 | URL에서 og:image 추출 | 파비콘 + 도메인 첫 글자 이니셜 배경 |
| 카테고리 배지 | AI 분류 결과 | "미분류" 배지 + 주황 테두리 |
| 추천 레이블 | 오늘의 영감 섹션에서만 표시 | 없음 |
| AI 요약 | AI 처리 동의 + 요약 완료 시 | "요약 준비 중..." |
| 저장일 | 항상 표시 | - |

**카드 클릭 동작**: 원본 URL 새 탭 열기 + 클릭 기록 저장 (방치 타이머 리셋)

### 5.2 미니 카드 (팝업·검색 결과용)

```
┌──────────────────────────────────────┐
│ [파비콘] 링크 제목           [카테고리] │
│         도메인 · 저장일               │
└──────────────────────────────────────┘
```
- OG 이미지 없음, 1줄 요약만 표시
- 검색 결과(C-2)와 팝업(P-1)에서 사용

## 6. 새 링크 추가 플로우

### 6.1 대시보드 "+ 링크 추가" 버튼 (Phase 1 — 핵심 방법)
1. 탑바 버튼 클릭 → 인라인 모달
2. URL 직접 입력 → 제목 자동 추출
3. 카테고리 드롭다운에서 선택 (AI 추천 기본 선택)
4. 저장 → 대시보드 B-2에 즉시 카드 추가 + 백그라운드 AI 처리

### 6.2 HTML 임포트 (Phase 1 — 기존 북마크 일괄 가져오기)
- 온보딩 A-2에서 파일 업로드 → 일괄 처리
- Chrome·Safari·Whale·Firefox 등 모든 브라우저 공통 지원

### 6.3 팝업에서 저장 ⏳ Phase 3 (크롬 익스텐션 출시 후)
- 브라우저 아이콘 클릭 → 현재 탭 자동 저장
- 어느 페이지에서든 한 클릭 저장

### 6.4 우클릭 컨텍스트 메뉴 ⏳ Phase 3
- 링크 우클릭 → "Bookmark Alive에 저장" 메뉴

## 7. 공통 UI/UX 요소

아래 기능은 **4단계 전체에 걸쳐** 사용되는 공통 UX 요소.

### 5.1 벌크 에디트 (Bulk Edit)
- 체크박스로 여러 북마크 선택 → 동시 처리
- **동시 가능 액션**: 태그 변경, 폴더 이동, 카테고리 재지정, 삭제
- 대량 정리 시 필수

### 5.2 비주얼 썸네일 (Visual Thumbnail)
- OG 이미지를 썸네일로 표시
- OG 이미지가 없는 경우: 사이트 파비콘 + 도메인명 자동 생성 이미지
- **카드 뷰 그리드**: 3열·4열 선택 가능

### 5.3 드래그 앤 드롭 (Drag & Drop)
- 폴더 간 이동
- 카드 순서 변경
- 태그 재할당 (태그 영역으로 드래그)

## 8. 차별 기능 (Differentiators)

기본기 4단계 위에 얹히는 **Bookmark Alive만의 핵심 차별 기능**. 상세는 PRD §3.2 참조.

- 방치 링크 심폐소생
- 시즈널 & 컨텍스트 매칭 (시즌·관심사·랜덤)
- 리마인드 "오늘의 영감"
- 실행 메모

각 차별 기능의 상세 로직·트리거 조건은 MVP 단계 지나면서 별도 문서로 분화 예정.
